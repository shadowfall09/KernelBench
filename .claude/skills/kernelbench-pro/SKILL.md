# KernelBench Pro

Work from the checkout root with Python 3.12. Read `docs/AGENT_LOOPS.md` for the chosen mode and `docs/GPU_CONFIG.md` when selecting hardware. For a Neuron target, read `docs/NEURON.md` and start from `configs/trainium2.toml`. Reuse the user's configured device, backend, model and budgets. Local GPU work runs inside an existing Slurm allocation; configuration preview does not need a device.

## Run an automated experiment

Use `configs/a6000-one-shot.toml` or `configs/a6000-feedback.toml` as a starting point, adjusting the GPU to the actual verifier. Preview with `python scripts/run_batch.py --config FILE --dry-run`, then use the same config to run. CLI overrides are supported. Independent samples use `num_samples`; feedback candidates use `optimization_rounds`. Defaults for feedback are five candidates and 2400 seconds per sample.

The automated loop uses mini-swe-agent. Claude Code and LiteLLM are model adapters; the controller owns evaluation and source selection. Inside an active Claude Code session, use the interactive route below to implement the task yourself, or use an already configured LiteLLM provider for automation. Do not bypass Claude's nested-session guard or change authentication settings to launch another Claude process.

## Implement a task in this coding session

Prepare one task without launching a nested model:

```bash
python -m kb_workflows.agent_task prepare --config configs/a6000-feedback.toml \
  --generation local --evaluation local --start 90 --end 90 --num-samples 1
```

Choose the task and verifier backend from the user's request. For Docker verification, build the current project image first; queue and Modal verification use their configured credentials/services. The command prints the task directory, public reference, output path and feedback command.

Read only the supplied `model.py` for the task and implement `ModelNew` at the printed candidate path. Use `python verify.py` from the task directory for development feedback. Inspect correctness before speed; use profiler events to form a concrete bottleneck hypothesis, change the implementation, and resubmit within the configured candidate/time budget. Keep notes on changes that helped or regressed. The bridge retains the best development-correct source at finalization.

When `device_backend=neuron`, keep the `torch.nn.Module` interface and use native NKI kernels registered through `torch_neuronx.nki_op`; the verifier supplies `neuron` tensors. Use the configured vendor interpreter for device verification. CPU or NumPy proxy execution, legacy XLA packages, CUDA images and simulated timings do not establish Neuron performance. Preserve role dtypes and keep unsupported FP8 storage explicit. Profiling uses the native exporter and a private NEFF cache set before compilation; retain no_grad, pre-forward reference/RNG/oracle tickets, post-capture output verification and environment restoration. For offline schema 12.0.1 Parquet, read `docs/NEURON_WORK.md`: retain every selected shard/row, exact integer/null work facts, raw versus adjusted FLOPs and separate DMA traffic. Execution/site joins and kernel labels confer no source ownership or hardware-counter qualification; the Neuron execution model and formal gate remain pending. The reader only reads existing files; do not launch Explorer or devices when implementation only was requested.

For one-shot, produce one implementation and finalize without calling `verify.py`; execution feedback is disabled. A live coding session has unobserved model/tool calls, so it is recorded as `interactive`, not as a measured one-shot experiment.

Freeze the chosen source:

```bash
python -m kb_workflows.agent_task finalize --directory TASK_DIRECTORY
```

Then run the native `evaluate` and `analyze` stages with the original parent run name, task selection, hardware and precision. Use `baseline` first if there is no current matching baseline. These final stages perform standard and hidden verification. Do not revise the frozen candidate in response to held-out failures within the same experiment; start a separately labeled run for further development.

## Preserve the experiment contract

- Do not inspect hidden tests, recover stripped inputs, change tolerances, or modify the evaluator/reference to improve a result. Preserve output structure, shape, dtype, parameters and input-dependent behavior.
- Development feedback uses standard tests only. Final hidden checks do not enter the automated conversation or candidate selection.
- For restricted verification or rule/library upgrades, read `docs/ISOLATION_REGRADE.md`. Keep the configured Docker/Harbor restrictions and use frozen-artifact regrading when the request is to reassess saved candidates. Its CLI previews by default; use `--execute` only when running experiments is within the user’s requested scope.
- For execution-origin work, read `docs/KERNEL_ORIGIN.md`. Its CUDA/Triton collector runs separately and previews by default. Wheel-bound cubins, Graph replay snapshots, supported template/executable kernel-parameter updates, observed Triton frontend/emission and CUDA object builds have diagnostic adapters. Preserve v1/v2 non-NULL CUfunction identity, node/executable/context events, update generations, cloned aliases and launch boundaries. Template updates must retain existing executables; executable updates must retain templates, sibling executables and old launches. Missing events or ambiguous update effects invalidate later association. Do not reuse an old node merely by retaining its handle or roll back a snapshot. Whole-graph/other node updates and CUkernel remain unassociated. Keep full CUDA source literals and the reviewed compiler options when using that observer; outer wrappers, replaced artifacts and cache-only records confer no provenance. Unsupported Runtime loaders, updates, compilers and Neuron origins remain unknown. Never turn a source declaration, diagnostic track verdict or custom fraction into formal L1 evidence or replace scored times with profile durations.
- When configured, preserve sanitizer and repeat checks. Read `docs/TOOL_CHECKS.md`; do not disable tools, edit task atomics policies or treat missing diagnostics as passing. Instrumented times never enter performance scores.
- Preserve configured `state_validation`. Read `docs/STATE_VALIDATION.md` when renaming or packing state: use the declarative `kernelbench_state_map` for registered views and `@` ordinary tensor paths. Keep source-bound `state_policy`, continuous state replacement and registered parameter storage rules. L3/33 hidden is persistent; L3/41 self.h0 is unused initialization, while its h0 input remains required. Preserve tied state, per-owner modes and cache invalidation under updates; mappings cannot waive comparisons or execute decoders. Nonlinear representations must retain mapped canonical parameters; unsupported storage/objects stay unqualified.
- Preserve configured `numerical_validation` and `oracle_memory_mb`; read `docs/NUMERICAL_VALIDATION.md`. Its L1 formulas, L2 composite arithmetic and L3 model algorithms cover all 250 original tasks on actual native inputs and require reference self-qualification. Read `docs/COMPOSITE_NUMERICS.md` and `docs/MODEL_NUMERICS.md` for frozen constructors, explicit recurrent/attention/Swin/SSD semantics and native dropout-mask replay. Meta plans supply shape/layout only. Keep the current hidden state, causal masks, batch-first direction, source literal rounding and unused-layer behavior. L3/35's omitted states keep their default-FP32 source behavior; do not repair it silently. Do not disable dropout, substitute small unit-test configurations, resize inputs, loosen budgets or fall back to reference double-forward. Unsupported/over-budget paths stay unqualified; full L0, full-population calibration and device evidence remain separate requirements. Read `docs/TIMED_NUMERICS.md`: numerical validation requires first/warm/measured and paired-output FP64 receipts even without an input profile. Preserve per-output scopes, pre-forward truth and program/mask evidence; extra correctness checks cannot replace timed checks. Paired outputs share one pre-forward ticket without extra oracle forwards. Keep verification outside scored intervals and restore actual post-candidate RNG on failures.
- When `precision_calibration` is configured, read `docs/PRECISION_CALIBRATION.md`. The reference-only fitter uses three fixed fitting seeds and three disjoint check seeds, isolated initial state and independent FP64 truth. Preserve the frozen margin/floor, original caps, all five scaled budget terms, raw errors, distinct input probes and direct held-out gates. A failed reference or check cannot widen budgets, refit on check data, drop the task or fall back to an old comparator. Fit only after any input-profile selection and apply that profile once. Freeze the file and task/sample range before candidates; private child bundles and regrading must retain content bindings. The effective budget requires a matching baseline. Same hardware/software classes may reuse the numerical policy with separate calibration/execution identities and mandatory current-device FP64 self-qualification; that is not a new device calibration. Different classes need separate configurations. CPU/simulated fixtures cannot establish device thresholds. The command previews by default; do not execute calibration in implementation-only work.
- When `input_calibration` is configured, read `docs/INPUT_CALIBRATION.md`. Its source-bound nominal menu covers all 250 original tasks. Keep fixed input/forward seeds, oracle/model/mask evidence, output-probe diversity and unchanged error budgets; constant answers cannot qualify from input diversity alone. Preserve group sampling, actual factory geometry and matching new baselines. Timed model checks require a pre-reference-forward FP64 ticket and matching RNG/state, including paired/Neuron calls; do not compute truth from already advanced state. A transferred distribution is not device measurement evidence. Unqualified references remain recorded and cannot be dropped after seeing candidate results. When `reference_population` is configured, preserve its preregistered qualified/excluded ledger and run snapshot, including sample counts. Read the population section in `docs/INPUT_CALIBRATION.md`; missing or incomplete/worker/resource-failed calibration is unresolved, never an exclusion. Freeze before candidates; retain later failed/missing samples as zeros. Keep parent population bindings in private Harbor/agent subsets and explicit RL task delegation. Never retroactively adopt a new population in an existing run. The freezer reads existing records only and defaults to preview; `--write` writes a new manifest without device execution. Calibration previews by default; never add `--execute` when implementation only was requested. Do not transform held-out factories, implicit states or reference parameters to obtain passing results.
- Read `docs/OPERATOR_INPUTS.md` for default L1/L2/L3 hidden families. Preserve constructor parameters, sequence/state/residual shape coupling, discrete roles, positive strides, storage offsets and input aliases. Keep group-preserving input transfers/snapshots; outputs retain their separate validation path. Actual-weight cancellation must read current reference coefficients without replacing parameters; meta receipts cannot qualify it. GELU/extrema cases and all 2551 cases per seed remain required. L3/33/48/49 have explicit fixed-shape reasons; never invent broadcast or replace state to shrink them. Keep `input_family_memory_mb` and full case/seed/native-call/copy-layout receipts; heavier alias cases require explicit extra memory, never omission. L2/L3 replay also checks exact shapes and dtype. Never skip an over-budget case or resize LayerNorm parameters. NaN/Inf cases apply only to declared tasks; null finite-error measurements do not supply reference signal. Input patterns do not prove internal saturation or final-output sensitivity.
- Preserve configured `allocation_validation`; read `docs/ALLOCATION_VALIDATION.md`. Its two fresh CUDA correctness workers poison observed candidate allocations across import, construction and native calls. Keep both patterns, environment, case/order receipts and the final unpoisoned control. Their timings never replace scored samples. Raw allocators, threads, Graph buffers and unsupported paths are not full device-memory evidence; do not disable compilation or deterministic policy to obtain a passing control. Neuron rejects this option.
- Preserve configured `cache_validation` and `cache_memory_mb`; read `docs/INPUT_CACHE.md`. Its fresh worker updates the same Tensor objects for every native public/hidden case. Keep trusted public factories and source-bound hidden role recipes, storage aliases, continuous state, RNG replay and all three output snapshots. Constant reference outputs are legal; this check does not establish reference signal. Unsupported storage or insufficient memory stays unknown. Do not replace tensors, alter protected labels/scales/indices or use these diagnostic calls as scored timings.
- Preserve `throughput_validation`, calls/repeats and storage budget; read `docs/THROUGHPUT_VALIDATION.md`. Fresh public-only latency/burst workers use matching input bytes and stable per-call snapshots, with continuous state/RNG and mode/gradient/thread checks. Both modes include snapshot-copy costs; these times never replace native samples. A >10% review flag excludes qualified performance credit without relabeling the saved native answer as cheating. Do not drop snapshots, shrink nominal workloads, turn on launch blocking, reuse hidden factories or erase flags to qualify.
- Read `docs/REFERENCE_REVISIONS.md` for repaired tasks. Keep current reference, hidden-source and shared-input-generator bindings; do not relabel a legacy positive result as a current revision. Preserve reviewed scan cases, empty-output/null semantics, normalized KL probability transforms and ±1 hinge labels. State/numerical policies and oracle memory also belong to frozen repeats and experiment comparison groups.
- For work counters, read `docs/WORK_COUNTERS.md`. The Nsight CLI previews by default and requires explicit execution within the user's scope. Preserve raw per-launch integer counts, units, PID/context/device and unchanged tool/source/config bindings. Partial resource reports cannot separate A/E. Complete review must bind source/reference, input geometry, dtype, precision policy and device class, then replay same-physical-device calibration; do not infer FLOPs from tensor busy time or set measured flags by hand. Keep the single initial public forward, fixed initialization/forward RNG, output checks, mode guards and profiler stop on failure. Unknown, timed-out or incomplete captures retain failure artifacts. These counters do not establish full native/state/origin coverage, Neuron counters, formal scoring or physical GPU budgets. Do not run ncu when implementation only was requested.
- Profiler durations diagnose execution; final performance comes from the native synchronized-wall benchmark and matching baseline.
- Preserve the declared `baseline_portfolio`; read `docs/BASELINE_PORTFOLIO.md` for extended recipes and backend/layout variants. Keep source-bound `baseline_plan`, initial/per-call validation and all failed variants. Layout/input-copy and scoped preference costs belong to the declared pipeline; compile/format setup belongs to cold cost. cuBLASLt preference does not prove actual library use. Do not shrink the portfolio, drop failed records, change eps/roles/precision or substitute unverified faster samples. Preview with `--dry-run`; do not record baselines when experiments are outside scope.
- Read `paper_analysis.json`, `generation_budget.json` and `phase_budget.json` when reporting results. Missing costs/tokens/GPU billing remain unknown. Generated source, development correctness and final verified speedup are separate claims.
- Compare matching settings with `python -m kb_workflows.experiment RUN_A RUN_B`. Keep one-shot, feedback, external Harbor and interactive sessions separate. Report independent sample count and per-sample limits alongside outcomes.
