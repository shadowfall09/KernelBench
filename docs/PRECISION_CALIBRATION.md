# 参考专用精度阈值校准

这条可选路径为原L1/L2/L3的任务/dtype生成**不超过公布上限**的数值政策。它只运行可信参考和独立CPU FP64算式，不加载候选、不采性能样本。当前只有小型CPU/模拟回归；没有生成真实设备校准文件。

## 预览与配置

默认只预览任务范围、拟合/验证种子、拟合规则和内存额度；不导入Torch、不分配原题输入，也不创建输出目录：

```bash
python -m scripts.calibrate precision --config /path/to/device.toml \
  --output /path/to/new-precision-calibration.json
```

仅在明确要跑参考设备校准时增加`--execute`；本次实现没有使用该选项。命令复用local、Docker、Modal或HTTP队列后端，输出须为新文件，保留失败参考和worker错误。一个任务没有合格记录时不能静默删题或退回宽松预算。

后续运行配置：

```toml
[run]
precision_calibration = "/path/to/precision-calibration.json"
```

也可用`--precision-calibration FILE`，相对路径按TOML目录解析。它自动要求`numerical_validation = true`；原生标准/隐藏、冷调用、预热、每次正式输出与配对验证接受同一拟合政策。未配置文件时继续使用公布的初始政策。

若使用`input_calibration`，先选择并冻结名义配方，再拟合误差政策；配方只应用一次。记录绑定该输入记录的摘要，不能改配方、参数、参考或dtype后沿用阈值。之后先重录匹配的基线，再生成和验证候选；`stage = "all"`会依据完整基线请求指纹识别并重录政策不匹配的缓存。预览会验证所选任务的记录并显示有效政策，缺项、过期、未合格或模拟记录在模型调用前拒绝。

## 拟合与独立种子验证

每个任务固定原始构造和名义输入工厂，不缩小尺寸。参数初始化seed为42，前向seed也固定为42；每个样本使用隔离参考，不累积前一个样本的状态。拟合输入种子为811、1291、2027；验证输入种子为1729、2718、3141。两组种子不重叠，六份有界输入探针也须各不相同，不能用重复输入当独立验证。

实际存储的输入、参数和状态被交给独立FP64算式。参考首先须通过原有RMS与所有元素上限，以及结构、shape、dtype、离散值和NaN/Inf规则；参考在上限之外时不能通过拟合加宽预算。每个浮点叶子记录参考RMS误差占原RMS限值的比例，以及各元素绝对误差占原逐元素限值的最大比例。

令`u`为拟合组全部叶子/样本的最大预算使用比例。固定规则为：

```text
factor = min(1, max(1e-6, 4 * u))
fitted_budget_term = original_budget_term * factor
```

五个预算项一起缩放，绝对项为零时仍为零，任何项都不能超过公布上限。随后冻结这份政策，再运行验证组；每个验证样本还直接对拟合政策执行一次RMS/所有元素门。验证失败保留原factor、政策和失败，不用验证数据重拟合、扩大或回退。输出完全离散时保留精确比较，factor为1，并显式标记没有浮点阈值拟合。

固定的margin、floor和seed是公布的软件政策，没有通过设备实验优化，也不是统计置信保证。校准覆盖的是原名义工厂/可选配方和这些种子；六例不能证明所有隐藏形状、状态演进、未来输入或其他算法均满足预算。实际评测仍须逐例独立复核参考和候选，失格记录不能获得正分。

## 设备、批量工作流与冻结

记录保存校准设备UUID及现有硬件/软件身份字段。相同硬件/软件类别的其他设备可复用**数值契约**，支持原有多GPU批量运行；运行收据分别保存校准和执行设备身份，并明确不把复用称为新设备已校准。每个执行设备仍强制进行当前输入上的FP64参考自资格验证。不同类别拒绝复用；一次校准运行/研究分组不混合多个类别，按设备配置分别处理。

类别使用现有兼容字段：设备名称、capability、总显存、处理单元/L2信息、Torch、CUDA/HIP和driver版本；Neuron的现有driver身份还绑定其编译器/NKI版本。它不是完整二进制认证或性能、频率、功耗与可达性证据。[设备校准](HEADROOM_SCORING.md)仍是另一条性能证据路径。

生成、导出、基线、正式验证和分析前，运行目录冻结`precision_calibration_manifest.json`，绑定完整文件内容、类别和任务/样本范围。已有候选或结果不能补选阈值；更换/关闭文件、改范围或样本数不能沿用旧运行。需要更新验证规则时，使用新运行或[冻结工件重新评分](ISOLATION_REGRADE.md)。旧模型成本不会因此重新认证。

子任务只携带当前题/dtype的记录，Harbor把文件放在私有`tests`中；公开提示只展示有效误差政策。生成协议、预算、最终冻结、研究计划/导出、RL验证与重新评分都绑定文件内容和执行收据。初始预算、拟合预算与真实设备测量资格分别记录，不能只改外层摘要或“qualified”标记获得通过。

## 资源与证据

`oracle_memory_mb`是原尺寸CPU FP64的增量内存估计准入额度，不是RSS硬限制。值变换和FP64分配前先估计，实际存储精度转移后再检查。超额、不可执行、非信息输出或环境变化保持失败/未解决，不自动缩小、换dtype、放宽误差或省略样本。

记录包括原始/有效输入签名、输入/输出探针、逐叶误差使用比例、原/拟合数值门、参考信号、独立程序及原生mask收据。探针最多取每Tensor的256个确定位置，不是全内容哈希或随机独立性的证明。记录校验属于可信控制端的完整性契约，不是密码学或硬件认证；CPU/模拟标记不能建立设备校准资格。
