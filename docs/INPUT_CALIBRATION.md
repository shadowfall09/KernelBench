# 参考输入校准与新基线

这条可选路径为原L1/L2/L3全部250题实现**名义输入值分布的选择**。它先检查参考的数值资格和信号，再冻结第一个合格配方。校准不加载候选、不采性能样本，也不按速度挑配方。当前只完成软件、meta与小尺寸CPU/模拟验证；没有生成真实设备校准文件。

## 使用方式

先预览，不分配原题输入、不导入Torch，也不创建输出目录：

```bash
python -m scripts.calibrate_inputs --config configs/a6000-feedback.toml \
  --output /path/to/new-input-calibration.json
```

仅在获准运行设备实验时增加`--execute`。它复用配置的本地、Docker、Modal或HTTP队列验证后端，每题独立执行参考校准；输出必须是新文件。错误和所有已尝试的失败分布保留。没有合格配方时任务保持不合格，不回退到旧比较或缩小尺寸。

后续运行在原配置增加：

```toml
[run]
level = 3 # 原L1/L2/L3均可
input_calibration = "/path/to/input-calibration.json"
oracle_memory_mb = 4096
```

也可传`--input-calibration FILE`。路径相对TOML解析。它自动要求`numerical_validation = true`；只给文件路径不能跳过实际设备上的独立数值复核。先使用同配置的`baseline`阶段重新记录基线，再进行生成/最终验证。CLI预览会显示选中的配方，缺项、无合格配方、模拟记录或来源过期在模型调用前拒绝。

`oracle_memory_mb`仍是增量主机内存估计准入额度，不是OS硬限制。校准检查在值变换和CPU FP64公式分配之前完成；原题的输入工厂本身仍需分配原尺寸输入。原尺寸超出资源、不可执行或参考无法达到固定预算时，保留失败，不自动放宽政策。

## 分布及角色约束

配方顺序固定，输入分别使用42、123、456三个种子；三次前向均重放固定seed 42，使输出差异来自输入，而不是Dropout换了mask。每次使用隔离参考，不积累先前试验的状态。优先尝试原始分布，然后尝试对应算子的合法变换：

- 普通浮点输入可尝试有符号或正值分布；整数、bool、标签和非Tensor参数不变。对称/上三角/下三角结构保留。
- L1/90累计乘积增加有界随机前缀配方。每个前缀为随机的有符号二次幂，幅值在1/8到8之间，FP16/BF16也保持可表示信号；沿原轴和原尺寸生成，并非固定答案。
- KL保留正概率及行归一化，另有概率峰值配方；triplet增加合法的分离嵌入配方；cosine标签保留。
- 七个池化/极值题另加正态配方。低精度下，大量uniform值的最大值可能三个种子都舍入为1；新CPU FP16反例先拒绝三个旧配方，再用合法的正态值获得变化的极值，不改归约尺寸或精度。
- L2/L3按来源绑定的融合卷积、线性、视觉/MLP、循环、attention、descriptor和state-space角色，声明正态、小正态、对称增益或正值配方。仅变化外部浮点特征和显式h0/c0，内部mask、参数、偏置及隐式状态保持原样。原始工厂仍被调用，batch/序列/残差耦合尺寸不变。

当前菜单共1039个分题配方声明：L1为308，L2为500，L3为231；这是候选菜单，不是执行次数。L2/L3按完整存储组采样一次并恢复视图，保留shape、dtype、stride、offset、共享关系和重复对象身份；输入不被原地污染。

每次实际浮点存储值交给独立CPU FP64公式/模型算法，参考原dtype输出接受RMS及逐元素门。L1一般叶子非零比例至少90%，三角矩阵与ReLU允许40%；L2融合允许10%，L3视觉/MLP和attention允许40%，其他模型使用90%。这些是公布的初始选择政策，没有用设备实验拟合；不能反向修改到某个参考恰好通过。

三次有界输入探针须各不相同，固定前向RNG下的输出探针还须至少两次不同。非零但完全忽略输入的常量参考也不能只凭输入变化合格。标量输出不因单个Tensor内没有方差而被误判，只检查跨输入变化。探针最多取每Tensor的256个确定位置，不是全内容哈希、输入敏感性证明或所有退化情况的穷举。

误差政策来自冻结的250题规格，绝对项收紧为零，其余相对/全局尺度项不放宽；非零真值不能因此被零答案替代。失败配方不能修改政策后重标通过。该过程选择输入分布，**没有从设备误差分布拟合阈值**，也不证明所有未来随机输入均合格。

## 基线、计时与隐藏输入

记录、配方、精度政策和评测器摘要进入请求。新请求与旧分布的基线指纹不同；基线恢复和评分还核对校准执行收据。基线首输出、warmup、每个计时输出，以及候选和配对计时的所有输出，都在同步墙钟区间之外做独立FP64检查。超过内存额度、参考失格、候选失格或收据计数缺失不能获得正结果。校准输入模式的FP32基线/配对参考关闭TF32，使用完整FP32算术；不为参考放宽预算。原墙钟性能样本不被诊断时间替代；这些检查的主机/设备开销仍可能影响整体运行条件，尚未做实机验证。

L2/L3必须使用**参考调用前**的真值票据：先按当前状态计算FP64真值并恢复RNG，再运行参考和比较输出。只在参考调用后读取状态计算真值会把BN/RNN更新或Dropout掩码错配。原生基线/候选、配对回调及Neuron双向调用均使用该顺序；配对验证恢复当前trial的前向seed。输入转移、计时快照和Graph静态输入按组保留别名，输出仍沿用独立快照。

值配方可在多GPU工作流中复用。收据分别保留校准设备和本次执行设备身份；复用的是分布，不是设备测量、性能校准或可达性证据。每个实际设备仍要执行强制独立数值检查，候选/基线兼容性按原有设备检查执行。

这里只包装可信名义`get_inputs`入口。隐藏输入工厂不自动套用所选值变换，以免抹去原隐藏分布；最终隐藏检查仍须在其实际输入上通过同一固定预算。隐藏输入因此可能独立失败。辅助小实例资格也不能冒充原尺寸名义分布资格。

## 冻结、传递与证据

记录包括参考SHA、评测器SHA、独立oracle规格、选择/精度政策、校准设备、所有尝试及三个输入种子的数值/信号报告、固定前向seed、内存估计、原始/有效输入签名与输入/输出探针摘要。复合与模型路径还核对冻结程序和原生随机mask收据。摘要校验是完整性核对，不是签名认证或候选安全沙箱。模拟执行不能成为正式校准文件。

配方和政策进入生成提示词。子任务只携带当前题/精度的记录；Harbor将文件放在私有`tests`中，公开指令只展示值分布及误差政策。文件内容摘要进入最终冻结、研究比较、RL计划和重新评分所用契约；改变内容不能沿用旧证据。候选恢复同时核对执行设备、配方、名义工厂调用及独立计时输出检查数。

没有合格配方的题目保留全部尝试，不能生成可评分的该题校准请求；L2/83的恒零公式继续不合格。不配置资格集合时仍要求所选题目都有合格记录。下面的可选入口允许在候选前固定合格参考子集；不能事后删掉模型失败来改分母。R-05的有限软件范围已完成；阈值校准与未配置输入校准时的完整计时数值门由R-04继续实现。

## 在候选生成前冻结参考资格集合

配置先指定已有`input_calibration`和原题目范围，暂不设置`reference_population`。预览只读取已有记录，不导入Torch、不分配输入、不调用模型或worker，也不采样时间：

```bash
python -m scripts.freeze_reference_population --config /path/to/calibrated-run.toml \
  --output /path/to/new-reference-population.json
```

增加`--write`只将清单写入新文件，仍不运行实验。没有实际校准文件时保留代码和预览入口；不能将CPU/meta/模拟夹具改标为设备校准来取得资格。本次实现没有创建真实校准或资格集合。

只有每个原定题目都有完整、来源和政策匹配的参考记录，才可冻结。合格题目保留第一个合格配方；不合格题目必须测完声明菜单，并保留每个配方的数值/信号失败、输入/输出探针差异和逐case摘要。缺项、未测完菜单、环境改变、worker错误、内存额度超限、执行异常、模拟或过期记录属于未解决，不能作为语义排除来缩小题集。合格集合为空时拒绝产生得分。

清单同时保存原题目/源码、精度、suite/role/track、评测器和完整校准文件摘要、合格与排除题目以及完整失败账本。后续配置增加：

```toml
[run]
input_calibration = "/path/to/input-calibration.json"
reference_population = "/path/to/new-reference-population.json"
```

也可使用`--reference-population FILE`，相对路径按TOML目录解析。正常批量范围必须与清单的原始范围一致；它不随候选表现重新选择题目。CLI的`--dry-run`显示实际题目与完整集合收据，不创建运行目录。

生成、Harbor导出、基线和正式验证开始前，运行目录保存`reference_population.json`，固定父清单、实际题目范围和每题样本数。已有候选、agent工作目录或评测结果的运行不能补选集合。恢复和评分须匹配原快照；更改排除项、校准文件、来源、范围或样本数不能沿用旧运行。启用清单后，生成、基线、标准/隐藏/最终/配对验证、评分、预算和研究分析统一选取合格集合；之后模型生成失败、缺失、错误或未通过的样本仍留在原分母中，取零分。

Agent/Harbor私有子任务只携带本题校准，但保留完整父清单及委托题号；公开指令不带其他题校准数据。RL的内部单题配置使用`reference_population_scope = "task"`，验证完整父清单并将实际单题范围单独写入收据。普通批量配置保持默认`"run"`；任务委托不能修改已冻结运行的范围或样本数。运行校准收据也必须含匹配的父集合摘要，基线/评分/最终恢复、研究契约和重新评分绑定该摘要及外部文件内容。

这是一份可信控制端的完整性与执行顺序契约，不是签名认证或对历史实验先后顺序的外部证明。参考入选只说明该校准文件的固定种子/配方达到政策；本次设备及未变换的隐藏输入仍须独立通过数值验证。实现见[资格集合](../kb_workflows/reference_population.py)、[冻结命令](../scripts/freeze_reference_population.py)和[软件回归](../tests/test_reference_population.py)。

CPU/模拟测试不代表任何设备或模型实验结果；本任务按用户要求不运行这些实验。实现见[模型配方](../kb_workflows/model_input_profiles.py)、[校准器](../kb_workflows/input_calibration_task.py)、[共享oracle准备](../kb_workflows/reference_oracles.py)和[回归](../tests/test_model_input_profiles.py)。
