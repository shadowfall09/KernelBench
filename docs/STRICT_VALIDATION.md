# 严格数值契约与证据等级

这是23项设计的第一批实现，推进R-04/05/06/07/09，并交付R-17聚合消融、R-22证据收据的代码。它是现有标准/隐藏验证之后的附加门：已有正确性、计时与证据门继续执行。

## 使用

```bash
# 原有协议仍为默认；显式开启附加契约。
python scripts/run_batch.py --config configs/a6000-feedback.toml \
  --strict-validation --level 1 --start 1 --end 3

# L0自动要求严格校验；原有GPU后端和Harbor使用同一配置。
python scripts/run_batch.py --config configs/a6000-feedback.toml \
  --evidence-level L0 --level 1 --start 19 --end 27 --dry-run
```

TOML中使用`[run] strict_validation = true`、`evidence_level = "L0"`。`current`是既有等级，L0/L1/L2要求在下表列出。不同配置分别比较，配置、契约文件和评测模块均进入恢复指纹。旧结果需要重评；不能只给旧JSON加等级字段。

当前适配17道L1：1–3、19–27、47–49、51–52。参考源码SHA-256、输入族、状态语义和各dtype阈值保存在随包分发的[契约清单](../kb_workflows/verification_contracts.json)。未适配题、参考漂移、无法构造oracle或缺失必要收据，在严格模式下不给通过资格。CLI会在创建运行目录或调用模型前拒绝含未适配题的严格任务；`--dry-run`显示覆盖范围。直接提交到worker的未适配任务也不会获得严格资格。

## FP64与输入范围

参考和候选分别在独立输入和模型副本上运行；可信参考的副本使用float64（比较工具也支持complex128）。转换保留整数、bool和嵌套结构。参考自己也必须满足FP64契约，否则该数值检查不成立，不用放宽阈值让候选通过。

每个浮点输出叶子同时要求：

```
RMS(candidate - oracle) <= norm_atol + norm_rtol * RMS(oracle)
每个元素的误差 <= element_atol + element_rtol * abs(oracle_element)
                  + element_scale_rtol * RMS(oracle)
```

最后的全局量级项允许合法fp32求和在接近零的元素上产生小误差；它也是显式契约参数。所有元素必须满足元素门。结构、shape、输出dtype、离散值和非有限值位置仍须符合契约。收据逐叶保存误差、限值、失败元素数和参考是否合格。

阈值目前是明确公布的初始契约，经过小规模真实CPU参考验证，并不是完成GPU误差分布校准的结论。附加实例使用小规模合法尺寸，避免构造原题巨大的FP64副本；**原尺寸计时输入仍使用既有比较器**。因此不能把L0解释成所有原始尺寸都已被FP64验证，也不能把这些实例的成本或耗时当作正式性能分数。

公开开发阶段只用第一组尺寸；隐藏阶段另外增加第二组奇数尺寸与非连续stride。矩阵相乘的维度联动，reduction保留合法维数；不缩放索引、mask或概率输入。输入族包括有符号数、近常数、宽动态范围、边界元素决定结果，以及GELU的±2.699辨别值。未核对的任务不会获得泛化扰动。

参考信号诊断记录有限值覆盖、最大值、RMS、超过绝对容差比例与常数标记。常数输出本身不判语义错误；要求至少一组合法实例提供有效信号。当前尚未自动修复所有原尺寸退化输入，也没有重建相应性能基线。

## 状态、缓存与进程设置

同一输入对象先运行，再原地修改后重跑；只有参考响应发生变化时，候选保持原输出才构成缓存问题。状态契约检查train/eval输出、参考声明的同名buffer和同名参数原地更新后的结果。候选状态重表示需要另行适配映射；缺少要求的同名状态不会被当作已验证。

候选首次原生评测、再次导入和附加调用都被进程设置审计覆盖。审计恢复后端精度/确定性设置、默认dtype、CPU线程数与环境变量，并把变更记录为失败。收据只含环境变量名称，不包含值。恢复和进程包装不是OS安全隔离，也不保证抓到候选在调用中修改后又恢复的全部行为。

## 等级与评分

| 等级 | 累计必要证据 | 当前状态 |
| --- | --- | --- |
| current | 本阶段原生正确性 | 默认协议；不提供完整执行合法性证明 |
| L0 | current + FP64契约、参考信号、合法输入族、输入敏感性、环境完整性、模式/状态 | 17道L1的附加实例已实现；CPU验证，GPU校准待完成 |
| L1 | L0 + 交替计时、噪声底、内核来源、设备校准、边界证书 | 缺少实际证据时拒绝该等级和相应评分资格 |
| L2 | L1 + 硬件计数器、内存安全、算法证书 | 尚未采集；不自动当作通过 |

每项记录`passed`、`failed`、`not_measured`或有理由的`not_applicable`，未知测量值为null。receipt同时记录请求等级、达到等级、缺项、standard/hidden范围；评分器重新根据逐项证据计算资格，不只信汇总布尔值。安全隔离认证仍为false。

原始正确性和计分资格有区别：原生输出正确但缺L1工具时可以保留诊断结果，评分资格则被拒绝。真正执行失败或严格必要项失败时，正确性也不能计作通过。`--no-hidden-tests`仍不代表已通过隐藏验证；报告明确记录是否启用。

## 聚合消融

`paper_analysis.json`新增`aggregation_sensitivity`，对同一批声明题目×样本槽位分别计算mean、median、best-of-N，保留失败/缺失零分和原资源收据。它显示同一批产物因聚合规则造成的变化，不增加模型调用、不修改正式mean评分，也不将未知预算认证为同等成本。跨生成策略的研究实验仍需真实模型数据。

## 验证范围

回归包含17道真实PyTorch参考的FP64/隐藏形状运行，以及BF16冒充FP32、GELU近似、单元素错误、结构/dtype/非有限值、输入身份缓存、参数缓存、BN计数器、环境恢复、秘密值不序列化、缺工具收据与聚合分母等反例。实际CUDA、所有题目适配、GPU阈值校准和生产模型实验分别验收，不以CPU测试替代。
