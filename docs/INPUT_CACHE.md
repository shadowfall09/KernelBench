# 同对象输入更新检查

`cache_validation`默认关闭。开启后，父进程在原生评测之后创建独立正确性worker，随后再运行直接正确性控制。原生性能样本、冷启动成本和候选源码保持来源绑定。

```toml
[run]
cache_validation = true
cache_memory_mb = 1024
timeout = 1800
# allocation_validation = true  # CUDA双模式候选分配预填
# throughput_validation = true  # 公开输入的同步/连续提交对照
```

每个实际通过的原生正确性实例都运行三次内容更新。参考与候选分别持有隔离输入组；三次调用保留各自Tensor对象身份。第一次写入原输入，后两次更新内容。调用顺序为C→R、R→C、C→R；每对调用重放相同随机种子，模型连续推进且不重置参数/状态。每次同步后立即保存输出，避免后续调用覆盖复用缓冲区，再按原生结构、shape、dtype、非有限位置和数值政策比较。配置了名义输入校准时，继续执行其独立数值复核。

公开阶段用当前可信名义输入工厂重新生成值，保持输入校准和生产输入角色。隐藏阶段不调用公开工厂：L1/L2/L3和生产41题使用来源SHA绑定的值配方，保持原shape、dtype、参数和输入耦合。对称/三角矩阵、正概率及归一化、±1标签、类别索引、布尔mask、有限前缀乘积、唯一top-k值都有声明规则。生产题目只更新自由激活、自由权重、唯一值和反向上游梯度，保留概率、mask、scale、页表、位置和其他离散控制。配方在检查候选前固定，失败后不换较容易的输入。

输入隔离保留重复Tensor对象、正stride、offset、存储别名及零stride广播；分离计算图并保留requires_grad和已有叶子梯度。更新通过原地复制提升版本计数。forward改变输入几何或替换其`.data`时，在同一Tensor对象上恢复保留的存储视图并记录恢复；这不等于恢复任意不同view间的PyTorch内部版本关系。复杂重叠写入、被破坏的底层存储、Tensor子类和未适配表示明确保留未知，不能作为通过证据。

分配两个隔离组之前，按完整底层存储S、逻辑输入字节I及真实参考输出快照估计O准入：公开为`2S+32I+6O`，隐藏为`2S+12I+6O`，覆盖输入克隆及工厂/配方、哈希和快照的暂存估计。额度1–1,048,576 MiB；超限不缩题、不减次数、不跳过后通过。该估计不包含模型权重、任意候选工作区、Python对象和进程堆，不是OS显存硬限。不会先构造真实权重副本或借小配置替换正式任务。

候选导入、构造、原生forward及更新forward有进程设置观察和恢复，包括环境变量、后端精度/default dtype、线程数、梯度及确定性政策；只保留变动的名称，不记录环境变量值。发现变动拒绝该诊断资格。根train/eval模式变化也拒绝。此观察限于所包围的调用，不能排除瞬时修改后恢复、任意后台线程或框架篡改。

收据保留每例label/seed/输入几何、别名、存储估计、值政策、三次派生种子/顺序、输入输出字节摘要、对象保留及几何恢复记录。父进程复核源码、设备、worker完成状态、完整原生覆盖和后续直接控制；评分与恢复重算收据。缺项、超时、不支持或设备不匹配不能获得资格。CPU/Neuron前端模拟只验证软件路径，不能建立真实设备资格。

参考可能合法返回常量；输出是否变化仅作记录，不因恒定输出认定缓存作弊，也不提供`reference_signal`资格。此检查测试同对象内容变化下的功能一致性，不证明GPU工作来源或不存在任意作弊。

R-09最初的四项设计是分配预填、同对象更新、吞吐对照和运行环境拒绝。它们已提供可选的软件路径；配置与限制见[分配预填](ALLOCATION_VALIDATION.md)、[吞吐对照](THROUGHPUT_VALIDATION.md)和本文。完整设备/线程/Graph证明不属于这四项的完成条件，执行来源及正式归因仍按R-08/R-16跟踪。按用户要求，没有运行GPU、Trainium或模型实验。
