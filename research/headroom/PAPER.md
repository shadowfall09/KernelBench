# Speedup Is Not Skill: Toward Reliable Evaluation of Agentic Kernel Engineering

**KernelBench Pro: an implemented workflow and a headroom-oriented research design**

Draft, unified on 2026-10-21. This is the current research manuscript. The implementation baseline is commit `92c27f4`; the accompanying integration adds the research selection and traceability records. [Motivation](../../docs/MOTIVATION.md), the [change ledger](../../docs/motivation_map.json), and the [version inventory](../../docs/FEATURE_INVENTORY.md) distinguish implementation from proposed mechanisms. The earlier HR-Eval and HEADROOM-Bench names denote the target evaluator and benchmark designs within KernelBench Pro. They do not denote two completed releases.

## Abstract

Evaluating generated GPU kernels requires more than measuring speedup over one PyTorch reference. Repeated tasks consume evaluation budgets; loose numerical checks can accept incorrect programs; baseline choice and startup accounting change the interpretation of speedup; and one-shot generation does not measure how an agent uses execution feedback. Reproducible infrastructure is necessary to study these questions at scale.

We organize KernelBench Pro around five motivations: task discrimination, correctness and execution validity, interpretable performance measurement, realistic agent interaction, and reproducible infrastructure. The current implementation combines the KernelBench-Verified task and hidden-test workflow with independent generation and verification backends, stricter output comparison, paired-order checks, multi-seed hidden validation, a validated four-variant baseline portfolio, synchronized wall timing with changing inputs, failure-inclusive evidence-gated scoring, and bounded mini-swe-agent sessions. It supports native one-shot and feedback protocols, Harbor tasks, and a skill for existing coding-agent sessions. The integration also exposes the supplied 105-task research selection through the same workflow.

The supplied research archive motivates a broader design: calibrated per-task inputs and FP64 precision contracts, hidden shapes, execution-origin attribution, measured device ceilings, algorithm-aware headroom scores, performance decomposition, production tasks, and a Trainium/NKI track. These remain explicit research objectives where implementation is absent. CPU and simulated regression tests validate workflow contracts; they do not establish GPU correctness, isolation, speedups, or cross-platform support. We retain historical audit evidence with its limitations rather than treating source review as device reproduction.

## 2. Motivation 1: tasks should discriminate at affordable cost

Many problems share computation patterns, and relatively few ask for an algorithmic change. Averaging many similar implementation problems can dilute the signal of a small design stratum. The archive's analyses suggest this redundancy, but fusion headroom alone cannot identify useless tasks: a single-kernel normalization can still leave substantial implementation room, while GEMM and convolution bounds depend on the algorithm and numerical contract.

### 2.1 Implemented task scope and selection

The default workflow retains Level 1–3, with explicit ranges and declared sample counts. Level 4 remains experimental. `--suite kernelbench105` selects the research manifest; ranges intersect with that selection. Every workflow stage uses the same IDs. An empty intersection is an error.

| Role | Tasks | Use |
| --- | --- | --- |
| scored | 105: L1 39, L2 40, L3 26 | Main research selection |
| probe | 5 | Audit diagnostics, reported separately |
| extended | 140 | Remaining coverage, reported separately |

The main selection's provisional strata are I=30 implementation, F=56 fusion, and D=19 design. The original procedure retains design candidates, groups other tasks by computation pattern and optimization type, and selects representatives using a public seed rather than model results. The manifest preserves every original membership decision and reason. Its name is standardized to KernelBench-105; the archive's `kb100.csv` filename was misleading.

These strata are descriptive research labels. Some design candidates were not certified, and some selected tasks have low-signal or degenerate original inputs. In particular, importing membership does not implement the draft's proposed input recalibration. Reference names and source hashes bind the selection to the reviewed checkout; changing a reference requires reviewing and versioning the manifest. No old tensor shape, input constructor, or baseline is silently substituted to match a historical study.

### 2.2 Target benchmark extension

The implementation now provides a separate `production41` suite in Level 5: 12 design, 6 numerical-design, 12 fixed-format implementation and 11 backward references. The original 250 tasks and the pre-existing Level 4 model files are preserved. These are software additions, not measured GPU results. The families follow the earlier draft’s categories:

- Algorithmic design: online/flash attention and backward, fused linear plus cross-entropy, Welford normalization, partial top-k, chunked linear attention and state-space scans, persistent or wavefront RNNs, FFT convolution, grouped MoE GEMM, dequantization fusion, and paged attention.
- Numerical design: precision emulation such as multi-pass low-precision matmul; choosing format, scaling block, and accumulation precision under an error budget; quantization fused with downstream work.
- Fixed-format implementation: production low-precision GEMM, grouped operators, decode attention, and related library-backed workloads.
- A separate backward track, with reference gradients and suitable high-precision checks.

The implemented families declare per-input storage roles, legal domains, hidden dimensions/strides and dynamic knobs. A deterministic memory plan uses the smaller of an explicit envelope and one tenth of device capacity, preserving shape constraints; this estimate is not a guarantee against arbitrary compiler/candidate workspace OOM. Four tracks are selected and scored separately, while their all-track collection macro is diagnostic. FP8 storage and packed INT4 are explicit. The FP4 quantization task defines software E2M1 semantics, not native NVFP4/MXFP4 throughput. All 11 backward families have FP64 gradcheck and directional finite-difference regressions. Existing baseline variants run through the same role-preserving path; the strongest baseline is the fastest validated member of the source-bound declared portfolio described below, without a global library-optimum claim. Design labels do not provide headroom eligibility without reviewed bounds and independent reachability witnesses. [Production tasks](../../docs/PRODUCTION_TASKS.md) lists every reference, representation and limit.

Selection-analysis software now exports current evidence-gated scores, compares full and selected populations with tie-aware rank statistics, bootstraps tasks/sessions/declared slots and reports missing scope explicitly. Constant score vectors have undefined correlation, not perfect agreement. Copied runs do not become independent sessions. A paired-binary normal design approximation is available under explicit assumptions, rather than replaying the draft’s unverified power numbers. Shapes within a task remain correlated instances; family correlation and selection-algorithm uncertainty are not automatically calibrated. Original seven-model raw data remain unavailable, and no compression/discrimination experiment is run in this scope. [Study workflows](../../docs/STUDIES.md) defines the inputs and limitations.

## 3. Motivation 2: passing a test should mean something

### 3.1 Diagnosis and its limits

The archived audit assigns each implementation its most severe source-review conclusion: 159 invalid, 60 unverifiable, 88 at risk, 217 in a small-speedup/noise category, 14 requiring investigation, 6 requiring explanation, 34 explanatory notes, and 996 with no issue found. Thus 219 is the sum of invalid and unverifiable records. Issue labels overlap: 346 records carry a noise label, while only 217 have noise as their final category. A displayed speedup ≤1.05 is a review threshold, not a measured confidence interval. Likewise, the 996 records are not GPU-certified correct implementations.

The records motivate checks for library substitution, unused custom paths, mode-dependent execution, weakened precision, low-output-magnitude comparisons, unstable statistics, indexing defects, cached parameters, and synchronization risks. A separate root-cause review in the supplied draft discusses representative implementations of 102 tasks, based on source review and counterexamples. Its counts and GPU detection rates have not been reproduced under the current harness. We do not attribute intent to every incorrect implementation.

The origin supervisor now reuses native evaluation in separate control and CUPTI processes with a common frozen timing-input plan. It covers both correctness call orders, all warmups and measured outputs, native hidden cases, and paired warmup/measurement schedules. Logical-byte hashes, geometry, storage aliases/offsets, modes and seeds are checked outside timed intervals, then bound one-to-one to source/launch windows. Host copies are streamed in bounded chunks. Activity filtering retains every overlapping unknown event and all queues for drop accounting; indexed interval joins avoid repeatedly scanning the entire activity stream. The control also has observation guards and synchronization, so matching observable traces does not prove equivalence to an unobserved scoring process. The actual CUDA allocator probe now joins this sequence as a separately verified memory call. Native numerical receipts require its own memory scope; raw peak, verification-copy allocation delta and adjusted peak are replayed. Other independent diagnostics are not joined here. Both stages remain diagnostic and cannot replace native scoring times or establish formal origin qualification.

### 3.2 Implemented correctness contract

Current standard and hidden checks share recursive comparison of structure, tensor shape and dtype. Integer and boolean tensors are exact. Floating outputs retain the existing dtype tolerances; NaN positions and positive/negative infinity positions must match before finite values are compared. Legacy tasks retain this contract; opt-in strict validation adds FP64 gates on reviewed auxiliary cases. A separate `numerical_validation` path now supplies independent CPU FP64 formulas for all 100 original L1 operators on actual native correctness inputs, without invoking their reference forward methods. Both reference and candidate must satisfy the same error contract. All 100 L2 tasks have source-bound composite FP64 arithmetic, and all 50 L3 tasks now have source-bound model algorithms, covering the original 250-task population. Reference-only nominal profiles and preregistered population freezing cover all 250 tasks. Timed-output numerical gates run independently of input-profile configuration. Optional reference-only threshold fitting now uses three fixed fitting seeds and three disjoint check seeds inside the published caps, before candidate generation. Production tasks additionally apply per-instance relative RMS and all-element budgets to declared reference outputs, so small magnitudes cannot make zero answers pass. Numerical-design references use FP64 arithmetic after prescribed quantization and round to declared output formats. A reference-output comparison is not independent FP64 self-qualification.

An optional `allocation_validation` path now runs two separate fresh correctness workers with candidate-only ATen allocation poisoning during import, construction and native paired calls. Floating/complex NaNs and integer/bool extrema are complemented by a second distinct fill, so matching a non-finite reference under the first pattern alone cannot qualify. Contiguous growth preserves the initialized prefix and poisons only newly exposed logical elements. Parent-owned startup disables the native CUDA caching allocator and enables synchronous launch errors; scored native samples are retained unchanged, and a final unpoisoned control must agree on case/seed coverage. The mode does not force deterministic algorithms or weaken tolerance. Source/request/device/pattern and window/call records are replayed for qualification and resume. Current-thread ATen observation does not establish raw-allocator, extra-thread, cached Graph or complete device-memory coverage; unsupported storage stays unmeasured, and Neuron rejects this option. CPU and simulated controls are software evidence only. The separate throughput contrast below is now implemented; full device execution integrity remains unfinished. See [allocation validation](../../docs/ALLOCATION_VALIDATION.md).

Optional `throughput_validation` now adds fresh public-only latency and burst workers. Both replay identical nominal input bytes, alternate reference/candidate order across repeats, preserve continuous state and RNG advancement, and validate every preallocated output snapshot. Copying snapshots is included in both diagnostic pipelines so reused output buffers do not erase earlier values; returned values must be ready for current-stream consumption. These times cannot replace native forward samples. Meta output inference admits retained tensor storage before numeric warmup without shrinking workloads; unsupported metadata and excess storage remain unmeasured. Root mode, no-grad, thread counts, settings and post-completion barriers are recorded, with input/output/source/device/call receipts replayed in the parent and scorer. Each repeat compares per-call times under a fixed 10% review threshold. A flag can reflect legitimate concurrency or overhead, not necessarily a wrong answer or tampering; saved native verdicts remain intact, while qualified performance credit is withheld. CUDA and Neuron share the software observer/synchronizer, with CPU queue and Neuron frontend simulations only. Background enqueueing, all-stream origin and complete device integrity remain unfinished. See [throughput validation](../../docs/THROUGHPUT_VALIDATION.md).

Reference and candidate receive separate input snapshots. Outputs are saved before another forward can overwrite a reused buffer. RNG state is replayed so stochastic operations face matching conditions. Paired-order checks run candidate→reference and reference→candidate, advancing each model equally. Separate source namespaces prevent candidate definitions replacing reference globals; shared backend settings are restored around candidate activity. These measures address specific contamination paths, not arbitrary host compromise.

Hidden input generators run under seeds 42, 123 and 456. For 29 reviewed Level 1 tasks, the first hidden configuration also receives zero, scaled and sparse-outlier variants, without changing shape, dtype or unreviewed input roles. No generic perturbation is applied to probability, mask, index or structural domains. Hidden sets that are empty, malformed, unavailable or fail in the reference cannot count as successful validation. The first general legacy additions did not provide hidden-shape coverage; reviewed scan tasks 89–93 now additionally cover odd shapes, strided layouts, rank-3 inputs, singleton and empty scan axes without changing the declared axis or mask roles. Opt-in strict contracts separately cover odd-sized and non-contiguous auxiliary cases for 17 reviewed L1 tasks. Production-41 has role-preserving private odd-shape, strided and dynamic-range cases, legal paged/masked variants, and near-constant normalization cases.

The source-bound L1/L2/L3 hidden portfolio now adds 2551 cases per seed (793/1170/588 respectively), retaining earlier cases and constructor-fixed shape exceptions. All 150 composite/model tasks declare feature axes and value roles for signed pairs, activation branches, isolated extrema and coordinate-asymmetric patterns. One hundred direct linear, standard-convolution or recurrent entries additionally derive a bounded two-product cancellation input from current reference weights, recording coefficient hashes and locations without changing parameters or bias. Fifteen L1 activations add finite ±32 and ±32752 values; exact/tanh GELU tasks include ±2.699 discriminators, and extreme reductions/pools have unique border values in actual windows. Every original task has nonzero-offset inputs; 33 reviewed multi-input tasks additionally share overlapping storage. Group-preserving transfer and isolated snapshots retain shape/stride/offset, aliases and repeated object identity, including all four paired calls in replayable receipts. Unsupported storage APIs and cross-dtype aliases cannot silently qualify. Alias storage requires a larger admitted envelope; no case is resized or omitted. These software families complete R-06's finite template scope, not universal bug detection: later layers or bias may hide a targeted intermediate, and L3 independent FP64 qualification remains separate. Validation uses small CPU cases, explicit Neuron frontend simulations and original-size meta layouts only. See [hidden input families](../../docs/OPERATOR_INPUTS.md). No device or model experiment was run.

### 3.5 Target numerical contract

The target evaluator distinguishes fixed-format tasks from error-budget tasks. A fixed-format contract declares all input, output and scaling formats. An error-budget task permits internal format selection but compares with a reviewed FP64 oracle, using a normwise bound plus an all-element bound; integers, booleans and non-finite handling remain explicit. Thresholds need legitimate implementation error distributions or format-derived analysis, published per task.

Input design has three layers: diagnose and repair non-informative reference outputs using legal inputs or parameters; instantiate operator-specific counterexamples; and vary hidden shapes and strides. Calibration inputs would also define the timing workload, while adversarial families remain correctness-only. Calibrating a reference changes the workload and requires new baselines and protocol labels. A constant-output task can be semantically valid, so degeneracy is evidence of a weak test rather than automatic proof that the task or candidate is wrong.

The intended precision gate should distinguish acceptable precision emulation from unacceptable single-pass lower precision under the same contract. This discrimination is an experiment, not an assumption. The first implementation supplies role-preserving FP64 oracle conversion and explicit initial thresholds for auxiliary instances of 17 L1 tasks (1–3, 19–27, 47–49, 51–52). Both the reference and candidate must meet RMS and all-element bounds. Element limits include an explicit global RMS-scaled term to accommodate legitimate cancellation error. With numerical validation enabled, original-size timing inputs also require independent FP64 checks, with or without distribution calibration. All 250 original tasks have source-bound adapters. Optional reference-only threshold fitting isolates initial state and fixes initialization/forward seeds, then fits a uniform five-term budget factor from three distinct input probes with a fixed margin and floor. A disjoint three-seed check group directly evaluates the frozen policy; failures cannot refit, widen published caps or fall back. Input profiles apply exactly once. All-discrete outputs retain exact comparison without a floating fit. Files and task/sample scope freeze before candidates; agent, Harbor, RL, final verification and regrading preserve bindings. Calibration and execution identities are separate: same hardware/software classes may reuse the numerical contract only with mandatory current-device FP64 self-qualification. This is not evidence of new-device calibration. Six nominal probes do not certify all hidden shapes, evolving state or future inputs. Empirical GPU error distributions and precision-emulation discrimination remain unrun. See [precision calibration](../../docs/PRECISION_CALIBRATION.md). The new numerical-design track now has task-specific budgets and FP64-derived mathematical references, while independent oracle qualification of every production path is still separate work.

## 4. Motivation 3: explain and compare performance honestly

### 4.1 Implemented baseline and timing protocol

The default baseline portfolio contains eager, torch.compile default, torch.compile max-autotune, and CUDA Graph. Variants run as independent tasks, validate initial and timed outputs, retain failures, and choose among valid variants. The suite's fp32 contract uses IEEE settings; explicit legacy single-baseline behavior is recorded separately. The optional extended portfolio now binds all 291 reference sources to a task-specific menu: six eager/compile/Graph combinations, 11 reviewed mathematical/library rewrites and 491 applicable backend-policy declarations, with Graph counterparts for every additional item. Named alternatives include SDPA/GQA, functional LayerNorm, correction-zero var_mean, residual RMSNorm, diagonal row scaling and norm forms; convolution tasks additionally nominate benchmark/layout policies, and BLAS/Linear families nominate a cuBLASLt preference. All 2,750 task/variant declarations retain initial and per-output validation, failures, source/recipe receipts and current scoring/recovery checks. Input/layout conversion and scoped preference dispatch belong to the measured pipeline; compile and model conversion belong to cold cost. A library preference is not execution-origin proof, and best means best among declared validated members, not a global optimum. Neuron retains its independent non-CUDA portfolio. R-13 software is implemented; all hardware/model experiments remain unrun. [Baseline portfolio](../../docs/BASELINE_PORTFOLIO.md) records exact semantics and pinned API sources.

Synchronized wall time covers host invocation, output consumption, and completion of device work. Input construction is outside the interval; each timed call uses newly generated inputs with recorded seeds, and its output is checked outside the timed region. Graph replay includes input copying and output cloning. A deterministic generator can still yield identical contents despite a different seed.

Raw millisecond samples, mean, median, standard deviation, an approximate normal mean interval, device/software fingerprint and input signatures are saved. Cold cost includes recorded construction/initialization, first execution and warmup; it is not a cache-cleared application launch measurement. For a declared call count K, the average is:

```
T_K = (T_cold + (K - 1) T_steady) / K
```

The default is K=10000; reporting K=1 or other values is configurable. Input preparation and process startup are not silently claimed as included. Profiling runs separately and never supplies official latency. The native allocator probe also verifies its actual output on isolated original inputs with the same numerical contract and pre-call Torch RNG. Reference verification and hashing follow the peak read, and the live verification-input allocation delta is explicitly removed from the raw absolute allocator peak. Both raw quantities are retained; resetting the peak alone does not remove already-live snapshots. Shared verification preserves the actual post-call RNG even on failure. This is an allocator measurement within the verifier process, not physical exclusive-memory certification.

### 4.2 Implemented scoring and recovery

Every selected task and declared sample contributes a slot. Failed, missing, stale, incompatible or evidence-incomplete slots receive zero. Current analysis uses all declared slots, first averaging samples per task, then macro-averaging task layers; it does not take the fastest sample. The report now computes mean, median and best-of-N sensitivity on the identical declared slots, retaining failures and cost receipts. This ablation does not change official mean scoring, spend additional model calls or certify unknown budgets.

Eligible comparisons require matching reference and kernel sources, evaluator version, input signature, precision/tolerance, device/software class, workflow configuration, raw timing samples, changing-input/verification receipts and cold costs. The strongest valid amortized baseline is selected at the declared K. A positive score additionally requires separated approximate steady-state mean intervals. Cold-cost uncertainty is not modeled by this interval test. When independent repeats or paired timing are enabled, their current measured samples and interval protocol replace the corresponding legacy steady-state values; incomplete or stale auxiliary evidence blocks the score.

Current bounded gain is:

```
G = clip(ln(T_ref,K / T_candidate,K) / ln(1.25), 0, 1)
```

This remains the default failure-inclusive measurement score. An optional certificate-gated headroom mode is implemented separately below; it does not turn these default numbers into measured headroom results. Two-level bootstrap resamples tasks and declared sample slots. Original Verified metrics remain available with their original formulas, subject to the measurement evidence gate. Correctness pass@k remains distinct from performance scoring. Raw stage diagnostics do not confer score eligibility.

Content-based recovery covers current sources, settings, hidden tests and evaluator modules. Generation recovery binds receipts to the candidate hash; explicit repeated attempts retain prior costs. Missing evidence is not converted to zero cost or successful verification. The scorer reports `anti_cheat_verified=false` and `cross_device_comparison_certified=false`. Suite roles and provisional label sources are explicit; probes and extended runs are not labeled as main-leaderboard eligible.

### 4.3 Target headroom score and certificates

The implemented optional headroom mode accepts device-specific calibration receipts and reviewed work-model certificates, rather than importing the historical spec-sheet ledger as measurements:

```
SOL_ref = max_k W_ref,k / rho_device,k
SOL_alg = max_k W_best_known_algorithm,k / rho_device,k
S = clip(ln(T_ref / T_candidate) /
         max(ln(T_ref / SOL_target), ln(1.25)), 0, 1)
```

The target can be the reference-graph bound for implementation/fusion tasks or the best-known-algorithm bound for design tasks. Minimum traffic, operation counts, legal numerical formats and resource ceilings must be explicit. A reference graph is not a universal bound: algebraic simplification or a better convolution algorithm can legitimately beat it. Recurrent workloads can additionally need a critical-path bound.

A design label needs a reviewed algorithmic comparison, a credible bound and a reference-device reachability witness; other devices may remain unwitnessed. Physically implausible latencies warrant investigation, not an automatic accusation based on a faulty bound. Optional scaling-exponent evidence needs multiple sizes and uncertainty estimates. The certificate reader binds the reference source, inputs, precision and calibration. D requires a reviewed algorithmic/numerical comparison and a reachability witness exported from at least two completed independent final standard/hidden verifications. Witness raw samples, source identities and distinct nonces are rechecked. A witness may belong to an explicitly recorded reference device; target-device reachability is reported separately. Imported provisional D labels do not meet this gate. Attained microbenchmark rates are model inputs, not proven physical upper bounds; below-model performance is an investigation flag. No calibration or reachability experiment is run in this implementation-only scope.

### 4.4 Target attribution and performance model

The desired separate profiling pass measures wall time T, the union of device busy intervals T_dev, kernel count, origin attribution, and optional operation/traffic counters. Overlapping kernel durations cannot simply be summed into busy time. The proposed explanatory model is:


## 8. Related work and limitations

KernelBench supplies the task-based kernel-generation setting, including earlier multi-turn experiments. KernelBench-Verified supplies inherited tasks, hidden value distributions and the TF32 baseline motivation. Hard, KernelBenchX, robust-kbench and TritonRL motivate multi-seed/domain-aware tests, granular diagnostics and ordering checks; [the reliability document](../../docs/RELIABILITY.md) records exact adopted methods and upstream versions. mini-swe-agent supplies the control loop; MLC/TIRx motivates a fixed feedback contract and separation of diagnostic profiling from timing, as recorded in [Agent loops](../../docs/AGENT_LOOPS.md). This integration does not import TIRx's compiler or checkers.

The supplied manuscript also discusses SOL-ExecBench, MultiKernelBench, production/low-precision benchmarks and measured-roofline tools. Those comparisons motivate the research plan; they do not establish that this implementation already surpasses their validation, profiling or hardware coverage. A publication-ready novelty claim needs a refreshed primary-source review and the planned experiments.

The audit snapshot, analytic ledger and public-kernel studies mix historical reference sizes and software versions. Some device identities were inferred; spec-based ceilings and meta traces have blind spots, especially on convolution algorithms and recurrent models. A reference-graph estimate is not a best-known-algorithm proof. Historical speedups and aggregate rankings must not be treated as newly measured data.

Other limitations are substantive: the independent actual-input algorithms cover the frozen original L1/L2/L3 population, not arbitrary Python models or exact real arithmetic. Strict auxiliary contracts remain limited to 17 L1 tasks; nominal value portfolios and preregistered qualified-reference population export cover the original population, and reference-only threshold-fitting code is implemented without device calibration data. State mappings are bounded and nonlinear representations require mapped canonical parameters. Constructor-fixed shape exceptions remain explicit; finite hidden families do not guarantee catching every shape/value bug or propagating targeted intermediates to observable outputs. CUDA counter capture/replay software is implemented; full custom-work attribution, full association between the implemented Neuron processing/demand model and native times/execution ownership, cross-capture joins and hardware qualification remain incomplete. No collected device calibration/reachability results, validated two-platform deployment, certified production security isolation or model/GPU experiment is supplied for the unified protocol. Bootstrap intervals do not remove shared-device drift, and diagnostics do not prove absence of races or cheating.

With `numerical_validation`, the actual first candidate/baseline cold output, native paired-order correctness outputs, all warmups, every measured candidate/baseline output and all paired outputs now pass independent actual-input FP64 gates, with no input-profile prerequisite. Oracle work, host copies and validation stay outside the scored intervals; source/precision/memory policies and per-output error, signal, graph and native-mask receipts enter a replayable timing audit. First, timing and correctness-control scopes have separate coverage requirements. Missing gates cannot be replaced by extra correctness calls or a re-sealed positive summary. Each paired trial freezes one pre-forward oracle ticket and validates all three outputs against that ticket without extra oracle forwards, preserving continuous ordinary state and RNG. Verification failure still restores actual post-candidate RNG. Native and Neuron paths, baseline cache admission, positive score gates, final remeasurement and recovery share this contract. Numerical-mode FP32 baselines disable TF32. Existing budgets and original dimensions remain fixed. These checks add untimed overhead whose hardware effects have not been measured. Optional reference-only threshold fitting is implemented inside the published caps; its fixed-seed records are distinct from current-output qualification and do not establish empirical device-wide thresholds. See [timed numerical validation](../../docs/TIMED_NUMERICS.md). No device or model experiment was run.

## 9. Conclusion

KernelBench Pro connects practical kernel-agent workflows to five explicit evaluation problems. The implementation provides auditable generation, validation, measurement, scoring and recovery contracts; the research plan adds task discrimination, stronger numerical and execution evidence, and hardware-aware explanations. Each existing change is mapped to its motivation, and each remaining design has a recorded gap. The current delivery advances software and regression coverage; three designs remain partially implemented. GPU, Trainium, model and training experiments are outside this implementation-only scope, and their results remain explicitly unrun.

The implementation is organized by agents, evaluation, numerics, hardware, provenance, analysis, runtime and benchmarks, with data beside the responsible modules. Catalog checks reuse nominal meta models; the compact results page refreshes evidence gates and retains failed and missing slots. This maintenance does not establish new experimental results or device qualification.
